# 一键同步、备份与恢复

SyncNotes 在设置页的「备份与同步」里提供三件事：立即同步、备份、恢复。备份 zip 的格式与已有的「导出我的数据」、服务器 `admin export` 相同（`syncnotes-export`：`manifest.json`、`blocks.json`、可选 `device_views.json` / `pending_outbox.json`、`files/*`、`markdown/**`）。恢复也接受旧的导出 zip。

数据在服务器硬盘上仍然是明文，不会用密码加密存储（避免加密失败毁数据）。线路上的上传、下载和同步仍然走 syncnotes-seal。

## 立即同步

把本机尚未同步的修改（outbox）和还在传输的附件增量上传到服务器。已经同步过的内容不会重传。离线时会先重连，完成后给出条数或失败原因。

入口：设置 → 备份与同步 → 立即同步。设置里原来的「重传本地缓存」仍然保留，那是把本机已有内容再发一遍（服务器上更新的版本不会被盖掉），和增量同步不是一回事。

## 备份

原则是「实际看到了哪些，备份就能备份哪些」：

1. 若已连上服务器，先把本机缓存追平到服务器最新状态，再下载服务器导出的 zip（含笔记、消息、文件、文件夹、回收站、已读状态和附件字节）。
2. 把本机尚未同步的修改（`pending_outbox.json`）叠加上去，并补上只存在于本机的附件。
3. 离线，或服务器版本过旧、没有备份接口时，退回打包本机缓存（与「导出我的数据」相近，在线时仍会尽量补下缺失附件）。

备份不会改密码，也不会加密 zip。Android、Windows、Linux 都可以保存到本地。

## 恢复

用于换账号或换服务器：登录目标账号，选择一份备份 zip，确认后：

1. 客户端先自动打包当前账号的数据，并请你保存一份「恢复前备份」。若取消保存，会再确认一次；服务器端还原时仍会再写一份近期安全备份（`files/<用户id>/.pre-restore/`，最多保留 3 份）。
2. 把所选 zip 上传到当前登录的账号（走已有的分片上传）。
3. 服务器用备份替换该账号的块、附件、回收站和已读状态。备份里没有的块会被打成永久删除墓碑。密码、恢复码、登录令牌和用户 id 不变。
4. 已连接的设备会收到 `resync`，丢掉本地缓存后从 0 重新同步。

备份可以来自另一个用户名或另一台服务器，数据会写进**当前登录的账号**。

失败时会给出明确原因（格式不对、上传失败、找不到备份、服务器版本过旧等）。还原在数据库事务提交之前失败，则账号数据不变。

## 管理员命令

服务器运行中也可以用（与 `admin export` 一样走 WAL）：

```bash
sudo ./syncnotes-rescue.sh export bill bill.zip
sudo ./syncnotes-rescue.sh restore bill bill.zip   # 先自动备份当前数据
# 或
syncnotes-server admin export bill bill.zip --db ... --files-dir ...
syncnotes-server admin restore bill bill.zip --db ... --files-dir ...
```

Windows：`syncnotes-server.ps1 export|restore`。若用命令行还原时服务器正在运行，已连接的客户端会在收到 `resync` 前可能短暂看到旧数据；HTTP 还原（客户端「恢复」）会立刻广播重新同步。命令行还原后如果客户端没有自动刷新，重连或点一次「立即同步」即可。

`/health` 的 `features` 含 `backup` 时，表示这台服务器支持备份下载和恢复。
